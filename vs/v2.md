请基于当前项目里的 simple_ai.gd 做“增量升级”，实现 SimpleAI v2。
不要推翻现有结构，请保留现有入口函数和大部分方法名，在此基础上补评分逻辑与阶段判断。

【当前现状】
当前 SimpleAI 的行为大致是：
1. DRAW：优先 ADVANCE_PHASE
2. MOVE：选择 source_bp 最高的 MOVE_CARD
3. MAIN：优先 PLAY_CARD 的 CHARACTER（按 source_bp 最大），其次 FIELD，再其次 EVENT，再其次 ACTIVATE_EFFECT
4. ATTACK：优先 target_kind = PLAYER 的直攻；否则选攻击 FRONT_CHARACTER 且 source_bp - target_bp 最大的动作
5. BLOCK：默认选 source_bp 最高的 BLOCK
6. STEP_SWAP_CHOICE：选 choice_bp 最低
7. HAND_LIMIT_DISCARD：选 choice_bp 最高
8. fallback：NO_BLOCK > ADVANCE_PHASE > END_TURN > legal_actions[0]

【升级目标】
把现有 SimpleAI 从“静态优先级选择器”升级为“轻量评分式 AI”，但仍然保持简单、稳定、可读，不要引入复杂搜索。
目标是让它更符合 UNION ARENA 基础对战节奏。

【必须遵守的规则认知】
1. 攻击角色时，如果攻击方 BP < 阻挡方 BP，攻击方不会退场，只是攻击失败。
2. 阻挡通常是高代价行为，因为阻挡方更容易亏掉未来节奏。
3. 前线角色负责攻击/阻挡，场地只能在能量线。
4. MOVE 阶段不仅要看 BP，还要考虑本回合攻击人数和下回合能量线稳定。
5. Raid 应优先被视为“节奏爆发工具”，不是无脑最高优先级。
6. 玩家生命是核心胜负目标，直接攻击玩家通常比无意义解场更优。
7. 如果有明显斩杀线，必须优先斩杀。

【实现方式要求】
1. 不要重写 choose_action / choose_pending_decision 的接口。
2. 保留现有 _choose_draw_action / _choose_move_action / _choose_main_action / _choose_attack_action / _choose_block_action 等方法名。
3. 在每个阶段方法内部，从“挑第一个最合适动作”改成“给候选动作打分，然后选最高分动作”。
4. 尽量通过 action.params 和 snapshot 中已有信息实现，不要要求 RulesEngine 大改。
5. 如果当前 action.params 缺少必要字段，可以在代码中用 has/get 做兼容读取，并在注释里写出“推荐未来补充的参数”。

【评分设计目标】
请增加一个通用评分思路，但不要做成复杂框架。可以使用小函数拆分，例如：
- _score_move_action(snapshot, action)
- _score_main_action(snapshot, action)
- _score_attack_action(snapshot, action)
- _score_block_action(snapshot, action)

### 建议评分维度
1. lethal_bonus
- 如果某动作能直接导致对方生命归零，给予极高分

2. player_damage_value
- 能直接攻击玩家的动作明显加分
- 如果对方生命 <= 2，再额外加分
- 如果动作带有 damage / impact / damage 2 / attack trigger 等迹象，也应加分

3. board_presence_value
- 能增加我方前线角色数量或提高前线总 BP 的动作加分
- MAIN 阶段不要只看 source_bp，还要看是否登场到 FRONT_LINE

4. energy_curve_value
- 能改善下回合费用曲线的动作加分
- MOVE 阶段不要把所有高价值能量线角色都推到前线，避免下回合能量断档

5. raid_tempo_value
- 如果动作是 RAID，且能带来即时收益（例如更高 BP、切到 active、移到 front、触发 when played），加分
- 如果只是单纯更大身材但无即时收益，不要无脑高分

6. removal_value
- 攻击前线角色只有在“能清关键阻挡位”或“能清掉高威胁角色”时才高分
- 无意义地打不影响直攻路线的角色，分数应低于直攻玩家

7. preserve_board_value
- 对关键前线角色、可反打角色、唯一阻挡位要有保留意识
- BLOCK 时不要默认最高 BP 就去挡

8. low_value_block_penalty
- 如果这次只会受到低伤害，但阻挡会亏掉关键角色，则应倾向 NO_BLOCK
- 若不挡就可能被斩杀，则必须优先挡

【各阶段具体要求】

### MOVE 阶段
当前逻辑只选 source_bp 最高的可移动角色，请改成：
1. 优先把“本回合可形成有效攻击压力”的角色推到前线
2. 但如果该角色同时是关键产能单位，且我方下回合明显需要能量，不要轻易移动
3. 若 snapshot 能看出 front_line / energy_line 数量，则优先保证：
   - 本回合至少有合理攻击人数
   - 下回合能量线不至于崩掉
4. 对带 Step 的交换选择，优先换出价值较低、BP 较低、当前不急需留前线的牌

### MAIN 阶段
当前逻辑是 CHARACTER > FIELD > EVENT > ACTIVATE_EFFECT，请改成：
1. 若存在斩杀相关动作，优先
2. CHARACTER 不只按 source_bp 选，需综合：
   - 是否登场到 FRONT_LINE
   - 是否增加前线压力
   - 是否改善能量曲线
   - 是否是 RAID 且有即时节奏收益
3. FIELD 只有在：
   - 能量线还缺资源
   - 或该场地有明显持续收益
   时才高分
4. EVENT 不能再只是“有就用”，应优先：
   - 抽牌 / 赚牌
   - 直接伤害
   - 清关键角色
   - 提升当回合或下回合节奏
5. ACTIVATE_EFFECT 只在确实有收益时才优先，不要简单排在 EVENT 后面吃掉行动
6. 如果当前没有高价值动作，应该倾向结束阶段，而不是乱出低价值牌

### ATTACK 阶段
当前逻辑是优先直攻玩家，否则选 BP 差最大的打前线角色。请改成：
1. 若直攻可形成斩杀或高压血，优先级最高
2. 直攻玩家默认比“无意义解场”更高分
3. 攻击前线角色只有在以下情况明显加分：
   - 能清掉关键阻挡位
   - 能清掉高威胁角色
   - 能为后续直攻打开路线
   - 有战斗胜利收益
4. 如果 target_kind == FRONT_CHARACTER，不能只看 source_bp - target_bp
   还要考虑：
   - target 是否为关键阻挡位
   - target 是否当前处于 active
   - target 是否会明显影响我方下回合节奏
5. 如果 action.params 中可读到关键词或伤害信息：
   - 带 damage 2 / impact / when attacking / direct damage 的攻击要额外加分
6. 如果没有高价值攻击，允许提前结束攻击阶段

### BLOCK 阶段
当前逻辑默认选最高 BP 阻挡，请改成更保守：
1. 若存在“不挡就输”的情况，优先挡
2. 若能用低价值角色换掉高价值攻击者，优先挡
3. 若这次只是低伤害，且阻挡会损失关键前线或下回合攻击点，优先 NO_BLOCK
4. 若 legal_actions 中存在 NO_BLOCK，应认真比较而不是只当 fallback
5. BLOCK 的评分应综合：
   - source_bp
   - source 是否为关键前线
   - 对方攻击伤害大小
   - 对方攻击者是否关键威胁
   - 挡住后是否能明显减少损失

### HAND_LIMIT_DISCARD
当前会丢 choice_bp 最高的牌，这通常不合理。
请改成更接近“丢低价值牌”的策略：
1. 优先丢：
   - 低 BP
   - 当前费用过高且短期打不出的牌
   - 重复价值低的牌
   - 当前局面下不急需的卡
2. 避免丢：
   - 明显高价值事件
   - 关键前线角色
   - 可能形成下回合节奏爆发的牌

### STEP_SWAP_CHOICE
当前选 choice_bp 最低，可保留为基础，但请增加：
1. 如果某张牌明显是关键能量提供者或关键前线，不应轻易换出
2. 优先换出低价值、低 BP、当前局面贡献较小的牌
