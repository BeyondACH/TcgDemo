## 变更摘要

对 `docs/plan/refactor.md` 重构实施计划进行了全面审查与修订。基于当前代码库逐项核验了计划中的所有 Task，发现并修正了以下问题：

1. **移除不存在的 Task 0.2**（`_after_attack_state_change` 重复调用 bug）：经代码核验，`battle_resolver.gd` L230 实际调用的是 `_after_block_state_change` 而非 `_after_attack_state_change`，每条代码路径只调用一次 `_after_attack_state_change`，不存在重复调用 bug。该 Task 已从计划中删除。

2. **修正 Task 0.3（现 Task 0.3）删除范围**：原计划建议删除 L225-226 两行。经分析，L226-227 包含 `play_options` 已有 `raid_target_zone_choice` 时的回退逻辑，删除 L225 后是有意义的代码。修订为仅删除 L225 一行。

3. **修正 Task 0.4（现 Task 0.2）bug 描述方向**：`consume_timed_delayed_effects` 中实际丢弃的是过期类型为 `END_OF_TURN`/`UNTIL_NEXT_SELF_TURN_START` 的修饰符，而非其他类型。原描述写反了。修复方案（所有不匹配修饰符都应保留）方向正确，但原因描述已修正。

4. **重审 Task 1.1 EffectUtils 函数重复清单**：原计划声称 15 个函数重复，经逐函数搜索核验，实际仅 9 个函数存在重复（2-4 个文件）。`register_preview_ui_meta`、`get_preview_ui_meta`、`build_preview_pick_ui_meta`、`build_preview_reorder_ui_meta` 仅存在于 `target_selector.gd`，无重复。工作量从 2-3 小时缩减为 1-1.5 小时。

5. **Task 2.1 增加兼容性验证前置步骤**：GameManager 的 `_available_actions_for_card` 与 RulesEngine 的 `get_card_available_actions` 使用不同机制（直接区域检查 vs Action 系统），替换前必须运行对比测试确认返回相同 action 集合。风险等级从"中"调整为"高"。

6. **Task 2.4 增加执行顺序约束**：类型标注应在 Phase 2 其他重构完成后进行，避免代码移动导致标注失效。

7. **更新统计数据**：GameManager 实际 982 行（非 971），emit_signal 字符串形式实际 18 处，测试基线补充说明 test/ 下另有 9 个专项烟雾测试。
