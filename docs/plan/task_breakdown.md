# 任务拆解清单（基于 `codex/v1.0`）

> 目标：把 `docs/plan/milestone.md` 进一步细化为可直接执行的研发任务列表。
> 
> 拆解维度：
> - 优先级：`P0 / P1 / P2`
> - 影响范围：编译器 / 运行时 / 测试 / 文档
> - 验收标准：可直接作为完成定义（DoD）

---

## 1. 执行原则

### 1.1 优先级定义

- `P0`：直接影响当前支持能力是否可稳定使用，或会导致错误结算 / 非法绕过规则
- `P1`：直接提升 `SUPPORTED` 覆盖率，能显著减少高频 `UNSUPPORTED`
- `P2`：提升维护性、可观测性与持续迭代效率

### 1.2 开发顺序

建议按以下顺序推进：

1. 先修高风险运行时闭环问题
2. 再补高价值模板族
3. 最后补统计、快照、流程规范

---

## 2. P0 任务（必须优先完成）

## P0-1：组合约束恢复校验回归补齐

### 目标

确保手动目标选择在暂停 / 恢复后，仍严格校验组合约束，不能被非法输入绕过。

### 影响文件

- `core/effects/target_selector.gd`
- `core/effects/step_executor.gd`
- 新增或补充对应测试文件

### 任务内容

- 补充恢复结算场景下的数量上限校验
- 补充总 BP 上限校验
- 补充动态阈值校验
- 补充重复目标 / 非候选目标校验
- 补充互斥集合校验

### 验收标准

- 非法恢复输入会被拒绝
- 待决策队列保持一致，不会被错误消费
- 合法输入能继续完成后续结算
- 错误码语义稳定，可用于 UI / 日志展示

### 测试点

- `too_many_targets`
- `selection_sum_exceeded`
- `invalid_choice`
- `distinct_by=CARD_NAME` 边界
- `max_sum_provider` 动态阈值边界

---

## P0-2：choice 分支执行一致性回归

### 目标

确保 `SET_CHOICE_MODE` / `EXECUTE_CHOICE_BRANCH` 在暂停、恢复、默认值、空分支场景下行为一致。

### 影响文件

- `core/effects/step_executor.gd`
- 相关 effect resolver / 执行测试文件

### 任务内容

- 校验 mode 变量默认值逻辑
- 校验未命中分支时 fallback 逻辑
- 校验分支内 steps 为空时行为
- 校验分支内再触发手动选目标时的暂停 / 恢复
- 校验分支执行日志与上下文写入一致性

### 验收标准

- 分支选择结果与执行路径一一对应
- 分支内暂停后恢复不会串分支
- 默认分支逻辑可预测且稳定
- 分支内异常不会污染无关上下文

### 测试点

- `mode_var` 缺失
- `default_mode` 生效
- `default_steps` 生效
- branch steps 空数组
- branch 内嵌 `SELECT_TARGETS`

---

## P0-3：`RUN_COMPOSITE_IF` 串联执行回归

### 目标

确保复合条件步骤在条件成立、暂停恢复、局部失败时行为明确且可验证。

### 影响文件

- `core/effects/step_executor.gd`
- 相关端到端测试

### 任务内容

- 校验 `if_requirements` 全满足时执行全部 steps
- 校验 requirement 不满足时不执行 steps
- 校验链式 steps 中途暂停后的恢复
- 校验中间 step 失败时后续行为

### 验收标准

- 条件判断与步骤执行边界清晰
- 暂停恢复后 steps 顺序不乱
- 日志能反映执行路径

### 测试点

- 空 `if_requirements`
- 空 `steps`
- 中途 pause
- 单步失败后终止 / 跳过语义

---

## 3. P1 任务（优先扩展支持面）

## P1-1：分支子效果模板化（第一批）

### 目标

把当前只支持“选择分支外壳”的能力，扩展到“分支内具体子效果可结构化编译”。

### 影响文件

- `tools/compile_cards_effects.py`
- `tests/test_compile_cards_effects.py`
- `data/cards/*/cards_effects.json`
- `data/cards/*/cards_semantic.json`

### 任务内容

优先支持：

- 选择一项 → 单步伤害 / 抽牌 / 加 BP
- 选择一项 → 选目标后处理
- 选择一项 → 多步复合效果

### 验收标准

- 分支内部不再只输出 `PENDING_BRANCH_EFFECT`
- 至少 3 类高频分支文本迁移为结构化 steps
- 对应样例能力从 `UNSUPPORTED` 迁移为 `SUPPORTED`

### 测试点

- 事件卡分支
- 触发效果分支
- 分支内目标选择
- 分支内 requirements

---

## P1-2：`selection_constraints` 编译映射

### 目标

让文本中的“最多 N 枚 / 总值不超过 X / 动态阈值”自动落到组合约束原子上。

### 影响文件

- `tools/compile_cards_effects.py`
- `tests/test_compile_cards_effects.py`
- 可能涉及 `docs/rules/rule.md`

### 任务内容

支持把文本模式映射为：

- `max_count`
- `max_sum_bp`
- `max_sum_provider`
- `TARGET_SET_UNIQUE`
- `TARGET_SET_DISJOINT`
- `SELECT_TARGETS_BY_COMBINATION`

### 验收标准

- 新样例能产出组合约束结构
- runtime 能直接消费编译产物，无需卡级特判
- 样例至少覆盖固定阈值与动态阈值两类

### 测试点

- “最多2枚且总BP≤X”
- “从候选中选若干枚，总和≤来源值”
- “与前一段已选目标不可重复”

---

## P1-3：高频 `UNSUPPORTED` 文本族聚类与首批清理

### 目标

不是盲目补模板，而是先找出出现频率最高的文本族，优先清理最值钱的一批。

### 影响文件

- 编译辅助脚本
- 文档统计输出

### 任务内容

- 对当前 `UNSUPPORTED` 文本做归类
- 标记“可用已有原子表达”的文本族
- 输出第一批建议支持名单

### 验收标准

- 能列出 Top N 高频 `UNSUPPORTED` 文本族
- 每个文本族都给出“可复用原子 / 缺少原子 / 暂不建议做”判断

### 测试点

- 聚类结果人工 spot check
- 归类标签稳定性

---

## 4. P2 任务（提升长期效率）

## P2-1：支持率统计脚本

### 目标

每次编译后可直接看到支持率变化，辅助确定下一阶段开发重点。

### 影响文件

- `tools/` 下新增统计脚本
- 可能新增输出文档

### 任务内容

输出建议包括：

- 每个系列 `SUPPORTED / UNSUPPORTED` 数量
- 每个模板族覆盖数量
- 新增模板前后差异

### 验收标准

- 一次脚本执行可输出清晰报表
- 报表可用于 PR 描述 / 每日日志

---

## P2-2：原子复用矩阵

### 目标

让后续新增能力优先复用已有 requirement / step，而不是继续发散。

### 影响文件

- `tools/` 下新增分析脚本
- 文档输出

### 任务内容

统计：

- 每个 `requirement.type` 的使用次数
- 每个 `step.type` 的使用次数
- 高频模板对应原子覆盖情况

### 验收标准

- 能快速识别“已有但少用”的原子
- 能快速识别“高频文本但缺原子表达”的缺口

---

## P2-3：编译产物快照回归

### 目标

避免一次模板修改导致大面积退化而不自知。

### 影响文件

- 测试目录
- 编译脚本 / 快照工具

### 任务内容

- 建立重点样例卡快照
- 建立总量快照（支持数 / 不支持数）
- 建立关键字段快照（status / template_type / steps）

### 验收标准

- PR 中可快速发现能力退化
- 快照差异可读、可复核

---

## P2-4：新增能力准入 checklist

### 目标

把新增能力的开发流程固化下来，降低后续返工。

### 影响文件

- `docs/rules/rule.md`
- `docs/plan/` 下规范文档
- PR 模板（如有）

### 任务内容

每新增一类能力，要求同步交付：

- 原子定义或模板归类
- 编译样例
- 运行时样例
- 边界失败样例
- 文档 / 日志更新

### 验收标准

- 新能力接入路径标准化
- 后续 PR 描述结构统一

---

## 5. 推荐迭代安排

## Iteration A

### 目标

先稳住运行时高风险点。

### 建议纳入

- `P0-1` 组合约束恢复校验回归补齐
- `P0-2` choice 分支执行一致性回归
- `P0-3` `RUN_COMPOSITE_IF` 串联执行回归

### 迭代完成定义

- 所有新增 runtime 原子都有最小回归覆盖
- 暂停 / 恢复 / 分支 / 组合约束不再有明显漏洞

---

## Iteration B

### 目标

开始扩大支持面。

### 建议纳入

- `P1-1` 分支子效果模板化（第一批）
- `P1-2` `selection_constraints` 编译映射
- `P1-3` 高频 `UNSUPPORTED` 文本族聚类与首批清理

### 迭代完成定义

- 第一批高价值文本族实现 `SUPPORTED`
- 分支能力从外壳支持升级为内部结构化支持

---

## Iteration C

### 目标

建立持续优化基础设施。

### 建议纳入

- `P2-1` 支持率统计脚本
- `P2-2` 原子复用矩阵
- `P2-3` 编译产物快照回归
- `P2-4` 新增能力准入 checklist

### 迭代完成定义

- 支持率提升可量化
- 模板回归可自动发现
- 后续新能力接入流程标准化

---

## 6. 一页版执行摘要

### 当前最优先三件事

1. 补运行时高风险回归
2. 补分支子效果结构化编译
3. 补组合约束编译映射

### 当前最值得避免的事情

- 继续按单卡零散加特判
- 只补编译器不补 runtime 回归
- 新增原子但不做复用统计

### 建议的完成顺序

- 先 P0
- 再 P1
- 最后 P2

### 一句话结论

后续开发应从“修一张卡”切换到“补一个文本族 + 对齐一组原子 + 补一组回归测试”的节奏。
