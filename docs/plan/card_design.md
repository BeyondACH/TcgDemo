# cards_effects 未支持原子能力待办清单

## 当前状态

- 统计基线来自 `data/cards/cards_effects.json`（文件时间：2026-03-30 08:41）。
- 当前共编译 `99` 张卡。
- 当前为 `104` 个已支持能力、`25` 个未支持能力。
- 未支持能力分布在 `19` 张卡上，均集中在 `UA31BT/MMM-1-035` 到 `UA31BT/MMM-1-067` 这一批正式 raw 卡。
- 按时机分布：
  - `ON_ENTER`：9
  - `ON_PLAY`：6
  - `MAIN_ACTIVATE`：5
  - `ON_ATTACK`：2
  - `ON_LIFE_TRIGGER`：2
  - `ON_LEAVE`：1
- 当前 `cards_effects.json` 已不再是“0 个未支持能力”状态；后续文档、计划与验收都应以本文件和实际编译产物为准。

## 总体结论

- 这批缺口不应按单卡补丁处理，仍应按“可复用 requirement / target / step / value provider / play rule”补齐。
- 当前未支持项主要不是基础规则缺失，而是以下几类模板尚未收敛：
  - 指定名称 / 指定特征 / 指定区域存在判定
  - 条件替换阈值与动态数值
  - 检索 / 预览 / 重排 / 余牌去向的组合链
  - 对单个或多个目标授予临时能力
  - 从场外 / 牌库 / 手牌按过滤条件进行登场、回手、回收
  - 与 RAID 叠放底座、位置交换、费用减免相关的专用出牌规则

## 优先级 P0：高复用通用模板

- [ ] 从场外按过滤条件以指定状态登场到前线
  - 目标：支持“从 OUTSIDE 选择满足颜色 / 必要能量 / 消费 AP / 卡种过滤的卡，以 `ACTIVE` 或 `RESTED` 状态登场到 `FRONT_LINE`”。
  - 影响卡：`UA31BT_MMM_1_035`、`UA31BT_MMM_1_055`
  - 当前文本模式：
    - `035 ON_LIFE_TRIGGER`：从场外登场 1 张“必要能量 2 以下、消费 AP1、紫色角色”，且为 `ACTIVE`
    - `055 ON_LIFE_TRIGGER`：同模板

- [ ] 从牌库顶部预览后检索命中卡，并把剩余卡按指定去向重排
  - 目标：支持“查看牌库顶 N 张 -> 公开符合条件的 1 张或最多 2 张 -> 加手 / 登场 -> 其余卡按指定顺序置于牌库底或场外”的固定组合链。
  - 影响卡：`UA31BT_MMM_1_040`、`UA31BT_MMM_1_043`、`UA31BT_MMM_1_048`、`UA31BT_MMM_1_056`、`UA31BT_MMM_1_065`
  - 需要统一处理：
    - 命中卡条件支持“名称或特征”
    - “望む順”重排
    - 余牌分流到 `DECK_BOTTOM` / `OUTSIDE`
    - 命中后追加弃牌或追加授予效果

- [ ] 从手牌或牌库按过滤条件直接登场，并支持阈值替换
  - 目标：支持“从 HAND / PREVIEWED_CARDS 中选择满足能量、AP、颜色、名称、特征条件的角色登场”，并允许在场面条件满足时把阈值从 A 替换为 B。
  - 影响卡：`UA31BT_MMM_1_042`、`UA31BT_MMM_1_056`
  - 说明：`042` 需要“必要能量 1 以下，若满足场面条件则改为 2 以下”；`056` 需要“从预览到的 4 张中登场 1 张”。

- [ ] 预览 / 检索命中后追加弃牌成本
  - 目标：支持“若本次确实将卡加入手牌，则再执行 `手札 1 枚を場外へ`”这类后置步骤。
  - 影响卡：`UA31BT_MMM_1_040`、`UA31BT_MMM_1_043`

- [ ] 手牌过滤回收
  - 目标：支持“从 OUTSIDE 选择满足颜色 / 特征条件的卡加入手牌”。
  - 影响卡：`UA31BT_MMM_1_060`

## 优先级 P1：requirement / value provider 扩展

- [ ] 指定名称或指定特征在指定区域存在
  - 目标：支持诸如“自己的 `ENERGY_LINE` 存在〈鹿目 まどか〉”“自己的场上存在〈暁美 ほむら〉”“自己的场上角色全部属于 A/B”之类 requirement。
  - 影响卡：`UA31BT_MMM_1_035`、`UA31BT_MMM_1_036`、`UA31BT_MMM_1_042`、`UA31BT_MMM_1_055`、`UA31BT_MMM_1_062`、`UA31BT_MMM_1_066`、`UA31BT_MMM_1_067`

- [ ] “全场仅由指定名称集合构成”的场面 requirement
  - 目标：支持“自分の場にあるキャラが全て〈暁美 ほむら〉と〈鹿目 まどか〉のみの場合”这类全量约束判定。
  - 影响卡：`UA31BT_MMM_1_036`、`UA31BT_MMM_1_042`

- [ ] 动态 BP 阈值
  - 目标：支持“基础阈值 + 每有 1 张满足条件的我方角色再 +1000”。
  - 影响卡：`UA31BT_MMM_1_064`

- [ ] 条件满足时替换 BP 阈值
  - 目标：支持“默认 BP3000，若满足条件则改为 BP5000”这类替换式 requirement。
  - 影响卡：`UA31BT_MMM_1_066`

- [ ] 仅在“登场回合”可发动
  - 目标：支持 requirement `SELF_ENTERED_THIS_TURN`，不要回退为按卡标记。
  - 影响卡：`UA31BT_MMM_1_049`

- [ ] 仅在自身为 `ACTIVE` 时可发动
  - 目标：支持 requirement `SELF_IS_ACTIVE` 供主动技复用。
  - 影响卡：`UA31BT_MMM_1_055`

- [ ] 仅在自身 BP 达到阈值时可发动
  - 目标：支持 requirement `SELF_BP_GTE`。
  - 影响卡：`UA31BT_MMM_1_052`

- [ ] 事件“以某指定角色为对象使用时”的费用减免条件
  - 目标：支持事件或出牌规则层的“当选择到特定名称目标时，消费 AP -1”。
  - 影响卡：`UA31BT_MMM_1_067`
  - 注意：这应优先归入出牌 / 使用规则层，不应在效果步骤中硬编码。

## 优先级 P1：target / zone / play rule 扩展

- [ ] 与指定前线角色交换位置

  - 影响卡：`UA31BT_MMM_1_038`、`UA31BT_MMM_1_049`、`UA31BT_MMM_1_055`

## 推荐实施顺序

- [ ] 第一批先补“场外过滤登场”“预览检索 + 重排 + 余牌去向”“从手牌 / 预览区过滤登场”
  - 原因：可一次性消化 `035 / 040 / 042 / 043 / 048 / 055 / 056 / 065`

- [ ] 第二批补“指定名称 / 指定区域 requirement”“全场名称集合 requirement”“动态 / 替换阈值”
  - 原因：可继续覆盖 `035 / 036 / 042 / 052 / 055 / 064 / 066 / 067`

- [ ] 第三批补“授予临时能力”“RAID 元卡引用”“事件费用减免”
  - 原因：这批更依赖规则层接口冻结，适合在前两批稳定后推进

## 开发前冻结项

- [ ] 冻结“事件以某对象为目标时 AP 减费”属于出牌 / 使用规则层，不回退到效果步骤按卡判断
- [ ] 冻结“RAID 元卡引用”走统一叠放来源模型，不允许对单卡写专用取源逻辑
- [ ] 冻结“位置交换”走显式 zone / slot 规则接口，不把位置交换伪装成普通 `MOVE_ZONE`
- [ ] 冻结“授予临时能力”统一落到 keyword / delayed ability / static modifier 体系，不新增按卡布尔字段
- [ ] 冻结“查看牌库顶 N 张后的命中卡 / 剩余卡”上下文结构，避免每张检索卡发明自己的上下文字段

## 验收要求

- [ ] 每补一类原子能力，都要同步更新 `tools/compile_cards_effects.py`
- [ ] 每补一类原子能力，都要重新生成 `data/cards/cards_effects.json`
- [ ] 每次推进后都要复核 `SUPPORTED / UNSUPPORTED` 计数，并同步更新本文件顶部状态
- [ ] 至少补 1 条对应的最小对局或冒烟用例，覆盖新模板主链路
- [ ] 正式 raw 样例扩充后，`docs/cards_raw_minimal_duel_smoke_test.gd` 应维持通过
- [ ] 若改动触及 UI 待决策流或预览选择流，额外确认手牌区域不遮挡战场区域
