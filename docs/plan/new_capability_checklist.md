# 新增能力准入 Checklist

> 适用范围：卡牌 DSL/IR、编译链路、运行时结算原子、规则层接口变更。  
> 目标：保证新增能力以“可复用原子 + 可回归验证 + 可观察统计”方式接入。

## 1. 规则与契约

- [ ] 已确认不与 `docs/rules/rule.md` 冲突
- [ ] 已明确 Requirement / Step 边界（无混用）
- [ ] 已确认不是按卡硬编码（而是模板族或原子扩展）
- [ ] 若涉及 DSL/IR 扩展，已冻结字段与语义

## 2. 编译链路

- [ ] 已补对应编译模板或映射规则
- [ ] 已补编译器单测（成功样例 + 失败样例）
- [ ] 编译产物关键字段可稳定产出：`status/template_type/steps`

## 3. 运行时链路

- [ ] 运行时可直接消费统一 IR（无文本直执）
- [ ] 已补至少一条最小流程回归（暂停/恢复、分支、失败路径之一）
- [ ] 非法输入不会误消费待决策队列，错误 reason 稳定

## 4. 统计与快照

- [ ] 已执行支持率统计脚本并记录结果
- [ ] 已执行原子复用矩阵脚本并复核复用情况
- [ ] 已执行快照比对脚本，确认无意外退化
- [ ] 若有差异，已在日志记录变化原因

## 5. 文档与日志

- [ ] 已更新 `docs/plan/task_breakdown.md` 或 `docs/plan/development_plan.md` 的阶段状态
- [ ] 已更新当日日志 `docs/logs/log_yyyy-MM-dd.md`（中文）
- [ ] 中文文档已通过 UTF-8 重读校验

## 6. 交付验收最小包

每次新增能力，最少应提交：

1. 编译器改动（模板/映射）
2. 运行时改动（若需要）
3. 至少一条自动化测试
4. 一条统计/快照结果
5. 当日日志更新
